# 知识库架构

## 数据流

`Sources 原始证据 → Inbox 候选 → Concepts 单点知识 → Methodologies 组合方法 → Personal 真实输出 → Feedback 回流`

## 固定目录职责

- `00-收件箱·Inbox`：未经人工晋升的候选、审核入口和起步说明。
- `01-原始素材·Sources`：不可改写的第一手或外部证据。
- `02-概念·Concepts`：可独立表达、带来源和边界的单点判断。
- `03-方法论·Methodologies`：由多个概念、步骤、条件和反例组成的方法。
- `04-个人输出·Personal`：真实任务、交付物、决策和复盘。
- `05-工具集·Toolkit`：模板、提示词、清单和 Skill。
- `90-知识地图·MOCs`：人工可浏览的领域入口，不是自动生成的装饰图。
- `99-系统·System`：配置、状态、日志、审核、接续和交付台账。

## 命名

文件夹使用 `中文·English`。一级目录不可在初次引导中修改。领域可用对象表示：

```json
{"name_zh": "人工智能", "name_en": "AI"}
```

若用户只提供中文，Agent 应提出一个简短英文别名并放进确认单；脚本的安全回退是 `中文·Domain`。

## Diagnose 判断

诊断资料能否支持真实输出时，至少检查：

1. 是否存在可读取的原文，而不只是标题或链接。
2. 是否能追溯作者、时间或真实场景。
3. 是否包含用户自己的判断、案例、修改或反馈。
4. 是否覆盖某个高频任务，而不是只有零散收藏。
5. 是否有明确的敏感边界和可写范围。

把事实、推断、愿望和证据分开。资料数量不是可调用性的替代指标。

## 个性化边界

可改：名称、作者、目标、高频任务、3—7 个长期领域、素材类型、资产类型、二级目录、标签、frontmatter 枚举、复查周期、隐私策略、可选插件。

不可改：候选优先、来源可追溯、原始证据不改写、人工晋升、不静默删除、写后回读、失败不推进状态。
