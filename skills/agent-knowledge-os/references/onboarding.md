# 八步引导式个性化

## 对话规则

- 每次只问一个问题。先邀请用户用自己的话描述；只有用户说“不知道”、明显卡住或主动要求例子时，才给 2‑4 个与其目标相关的参考表达。选项是启发，不是必选菜单。
- 把用户当成第一次接触知识库的普通人。面向用户时不说 `Vault`、`Schema`、`frontmatter`、`MOC`、`ingest`、“资产类型”、“复查策略”、“只读路径”或“Restricted Mode”。这些词可以在内部配置中使用，但向用户提问和解释时必须换成大白话。
- 不要让用户自己想英文名、文件名或配置值。先听懂用户的中文表达，再由 Agent 生成简短名称放入确认单。
- 新库走完整引导；旧库先运行 `scan_existing_vault.py`，不重复询问已发现且无冲突的信息。
- 目标为 5—8 分钟，不在初次引导展开高级 Schema 设计。
- 收集阶段只在聊天和临时文件工作，不写正式 Vault。
- 最后展示确认单；只有明确确认后才运行 `bootstrap.py --confirmed`。
- 中断时将 onboarding 视为未完成，不产生“看似完成”的配置。

## 八步

1. **身份**：名字、称呼和用途分开问，不要一次扔出三个问题。先说：“先给这个资料库起个名字吧。你已经有想好的名字吗？”再问“平时我怎么称呼你？”最后问“你最希望它帮你解决什么问题？”
2. **首要任务**：不要把“首要任务”、“使用场景”这类词直接丢给用户。用大白话问：

   > 你平时最想让这个资料库帮你做哪件事？先说一个最常遇到的就行，按你自己的情况说，不用从选项里挑。

   先听用户说原话。如果只说“写内容”、“学东西”或“做工作”，再用一句话追问：

   > 能不能说说最近一次？你当时想找什么，最后想做出什么？

   用户确实不知道怎么说时，才给与其情况接近的例子，例如：

   - 写文章或准备直播时，能找到自己过去的经历、观点和说过的话。
   - 给客户做方案时，能快速找到以前的案例、方法和可以复用的文件。
   - 学一个新东西时，把看过的资料放在一起，以后能找回来并说清自己的理解。
   - 做产品或工作决定时，能查到以前的用户反馈、数据和当时为什么这样选。

   这些只是帮用户听懂问题，不是要求用户四选一。优先保留用户自己的说法。如果为了建文件夹需要缩短，由 Agent 提炼一个不改变原意的短名放入确认单；不要擅自换成“内容创作”、“学习研究”等笼统分类。先确定一个，有必要再补到最多三个。
3. **长期领域**：面向用户说：“除了刚才那件事，你还有哪些主题会经常用到，过半年也值得继续留着？”引导出 3—7 个，不把只做一次的项目当成长期主题。英文短名由 Agent 生成并放入确认单。
4. **来源类型**：面向用户说：“你平时想往里面放哪些东西？比如自己写过的文字、看过的文章和书、别人问过的问题、会议记录、项目文件，也可以直接说你自己的情况。”
5. **资产类型**：不要问“你要什么资产类型”。改问：“以后打开这个资料库，你最想直接找到哪些能拿来用的东西？比如说清一件事的短答案、做事的步骤、真实案例、可以套用的模板。”内部仍保留概念和方法论两类基础能力。
6. **复查与过期**：面向用户说：“哪些内容变得比较快，需要过一段时间提醒你再看看？”用户不确定时，用“平台规则经常变，自己的经历通常不会过期”这类例子解释，再由 Agent 给出建议时间。
7. **隐私与 AI**：面向用户说：“这些资料里有没有客户姓名、私人聊天、电话、账号或密码？哪些内容只能看，不能让 AI 改？”一次只问其中一个，再把答案记入隐私设置。
8. **Obsidian**：先在后台检查，不让用户运行命令。未安装时问：“你的电脑还没有 Obsidian。要不要由我帮你安装？真正安装前我会再把要做的事列给你确认。”询问插件时先说用处，再在括号里标名字：“要不要加上高级查找和汇总功能（Dataview）？”、“要不要加上一键套用模板的功能（Templater）？”两个分开问。安装 Obsidian 的同意不等于同意安装这两个附加功能。

`obsidian.app` 记录选择：已安装为 `use_existing`，授权补装为 `install_if_missing`，明确不使用为 `skip`。

## 确认单

确认单面向用户时也要用大白话，不直接显示配置字段。按下面的意思列出：资料库会建在哪里、会新建什么并保留什么、它主要帮用户做什么、会长期保存哪些主题、用户会往里面放什么、以后能从里面直接找到什么、哪些内容需要定期看看是否过时、哪些内容需要隐藏或不允许 AI 修改、Obsidian 是否需要安装、选了哪些附加功能，以及 Agent 明确不会做的事。结尾用一句话问“上面这些设置是否正确？你确认后我再开始创建。”这一次确认可同时授权创建资料库和安装 Obsidian，避免重复询问。

用户确认后，如配置为 `install_if_missing`，先运行：

```bash
python3 scripts/install_obsidian.py --install --confirmed
```

安装失败时报告具体原因与官方下载地址，仍可继续生成 Markdown 知识库；不把 Obsidian 安装失败伪装成全流程成功。

## 再次个性化

先 dry-run 展示字段差异与迁移计划。确认后只更新配置、章程和相关模板；不自动创建、重命名或移动领域目录。备份必须先于写入，修改记录必须可回读。
